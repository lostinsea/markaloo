### Document Undo/Redo and typing history

- Compact Undo and Redo buttons sit beside Save in the Markdown editor.
- Buttons and shortcuts use document history, not cell-editor history.
  They do not save the file.
- One Undo reverses a typing group. New typing clears Redo immediately.
- Typing and a subsequent table Update remain separate document Undo steps.
- Controls follow the active document and remain reachable in narrow panes.
- Included in the installed local candidate. Full regression and platform
  IME coverage are not claimed.

### Cell-editor opening and row controls

- Small tables open compactly; substantial text gets wider initial data columns.
  Opening estimates inspect a bounded amount of displayed content.
  These limits are not measured CPU, RAM or opening-time savings.
- Manual resizing, window-relative proportions and 48px data-column minimums
  remain. Tables scroll when the available width cannot fit those minimums.
- Outlined controls insert rows above/below or remove a data row.
  Every removal asks first, including empty, original and added rows.
- The true header cannot be removed. Changes stay in the popup draft until
  Update; surviving cells retain their native editing history.
- These earlier refinements are installed. The explicit highlighted-cell rule
  and revised initial allocation below belong to the newer source candidate.

### Rendered table column resizing

- Drag a column separator in the reader or editor preview to resize that column.
  Other columns keep their widths.
- Thin double-line markers keep a wider pointer target for easier dragging.
- Focus a separator and use Left/Right; Shift takes larger steps.
  Home or double-click restores automatic widths.
- Escape, cancellation, window blur, zoom or mode changes cancel an unfinished drag.
- Widths are view-only. They do not change Markdown, dirty state, Save or Undo.
  Completed widths last until the document renders again.
- Rectangular tables support resizing. Nested tables, spanning cells and HTML
  column groups keep automatic layout.
- Print and PDF are designed to retain automatic widths and hide the controls;
  those full regression routes have not been run for this candidate.

- Tables keep Clear Filters and Export, with CSV/JSON choices in the format menu.
- Trusted hidden Chromium Ctrl+wheel uses the same reader step once over text
  and Mermaid. The fitted SVG constraint remains.
- Hidden checks cover all three compact layouts, pointer-opened format menus,
  popup zoom/Reset, PNG/JPG canceled-handler routes and table Clear Filters.
- Actual printToPDF plus simulated Save cancellation restores the controls.
  This is not a real native Cancel check.

- Trusted keyboard checks cover disclosure opening, format traversal and

## Published changes: documents, editing and reliability

### Tabs, refresh and external changes

- Fixed the original problem: refreshing one tab no longer leaves another tab's
  cached content stale and restores that old text when switching back.
- Save and reload results update their originating tab, even after a tab switch.
- Clean background tabs refresh when selected. Dirty tabs are not silently replaced.
- File watching follows the active document and stops when the last tab closes.
- Dirty state follows document content, not a stale visual indicator.
  Newline normalization no longer creates false unsaved changes for Windows files.
- Refresh restores a heading and reading offset while images and diagrams settle.
  Delayed completions cannot move another tab or clear newer edits.
- File Updated belongs to the document being read and no longer expires before
  the reader acts. Cancelled reloads retain both the notice and unsaved work.
- Session restore activates the selected document once, rather than rendering
  every restored tab and asking repeatedly about expensive files.
- Restored the previously active file after restart instead of relying on
  regenerated tab IDs.
- Shared file reading keeps BOM removal and Mermaid-file normalization consistent
  across opening, restoring and refreshing. Standalone Mermaid files no longer
  turn into plain source text on those paths.
- Fixed a stale render leaving the app stuck behind Loading, and bounded deferred
  highlighting. Later work also avoids scheduling highlighting when there is none to do.

### Save, close and disk safety

- Serialized saves per file and correlated results with their requests.
- Leaving an editor after confirmed discard restores the correct baseline and
  history. Cancel keeps the editor and its changes.
- Retained failed and pending Save state separately from ordinary dirty state.
  A failed Save cannot become safe to close just because text matches an old baseline.
- Added coordinated close, quit and update-install protection for open documents,
  including asynchronous writes and stale answers.
- Bound file operations to admitted documents and disk versions, not a pathname alone.
  Deletion and replacement evidence survives long enough to protect an earlier copy.
- Rechecked ownership and disk state around reads, writes and adoption.
  Old callbacks cannot authorize a different document or retargeted file.
- Preserved original newline spelling when semantic text is unchanged.
- Avoided truncating every file to zero before rewriting it; only shrinking files
  need a final truncate.
- Clearer reload questions distinguish a returning file, a different file at the
  same location and an earlier protected copy. Genuine unsaved-edit questions stay separate.
- Same-size external edits with restored modification times remain a known
  detection gap. Separate Save-alias and shutdown follow-ups are not claimed solved.

### Document-owned editors

- Each tab keeps its own open/closed editor, draft, selection, Undo/Redo,
  scroll offsets and discard checkpoint.
- Repeating Open editor does not reset or rerender an existing editor.
- Save and Exit are separate. A pending Save keeps the editor open.
- A Save completion advances only its owning document's saved baseline.
  Newer typing remains unsaved, including after a background completion.
- Replacing disk content retires old Undo text. Closing a tab retires its editor;
  reopening starts in reading mode.
- Editor sessions stay in memory; drafts and Undo history are not restored after restart.
- Document-changing context-menu actions require edit mode.
  Notes remain available in reading mode and save on confirmation.
- Adapted upstream fixes for Edit Text selections crossing bold/italic boundaries,
  draggable pane sizing and viewport-bounded, resizable insertion dialogs.

### Visual table editing and Edit Text

- Added a rendered table-cell grid, with no separate Markdown source pane.
- Edit the clicked whole table or selected rows from either editor pane.
- Preserve surrounding prose, unselected rows, unchanged source spelling and
  authored formatting. Repeated tables are identified from source, not guessed from text.
- Update is one document Undo step, not Save. Cancel changes nothing.
- Tab moves between cells; Enter/Shift+Enter move down/up a column.
  Ctrl+Enter updates and Escape cancels.
- Typed backtick code, `**bold**` and `*italic*` format inside cells and survive
  Update and reopening. Continued typing and native cell Undo/Redo stay local.
- Ordinary cell edits no longer add editor-created HTML wrappers to Markdown.
  Only narrow literal-code cases use content-preserving `<code>` HTML.
- Multiline paste inside Markdown-owned inline code becomes spaces.
  Ordinary cell paste and authored HTML code retain their own newline behavior.
- Refuse unsupported, ambiguous or stale selections rather than changing the wrong text.
  Raw HTML tables, nested tables and ragged rows are outside the grid's supported scope.
- Added the same selective typed bold, italic and code formatting to Edit Text,
  through one shared formatting core.
- Edit Text keeps other Markdown raw and preserves captured source boundaries,
  native history and one document Undo on application.
- No underline, formatting toolbar or enabled popup formatting shortcuts.
  This is selective inline editing, not a full rich-text editor.

## Published changes: reading and rendering

### Navigation, toolbar and zoom

- Replaced the two-row toolbar with one bar, tab tooltips and tab actions for
  Copy Path and Open Folder. A single document remains a tab.
- Added drag-and-drop document opening using Electron's supported file-path API.
- Grouped Reload/Open editor separately from TOC and the menu.
  Document actions are disabled without an admitted document; empty files remain usable.
- Moved the TOC left and added current-section tracking through H1-H6,
  including skipped levels and long nested sections.
- Kept the current heading visible in the TOC without stealing document focus.
  Added accessible buttons, current-location state and inert hidden drawers.
- Remembered TOC, All Notes or closed-drawer choice.
  With no saved choice, the first admitted document opens its TOC.
- Preserved reading position when drawers open/close, tabs refresh and zoom changes.
- Raised document zoom's maximum from 200% to 400%.
  Saved one reading percentage across documents, reader windows and restarts.
- Fixed zoomed split-view heading/footnote positions and cancelled old scroll
  restoration after explicit TOC/search navigation.
- Fixed folding state leaking between documents and Collapse All/Expand All
  state being lost on rerender.
- Made search debounced, flushed pending work before match navigation and removed
  obsolete matches after rerender. Search controls wrap below the toolbar beside the TOC.
- Kept right-click and nested toolbar menus reachable in narrow/short windows,
  with bounded scrolling rather than clipped commands.

### Source and preview scrolling

- Linked both panes by matching source content, not equal scroll percentages.
- Track paragraphs, wrapped lines, list items, table rows and code lines.
  Images, Mermaid and sandboxed HTML use stable block correspondence.
- User wheel, scrollbar or keyboard input chooses the driving pane.
  Follower events do not create a scroll feedback loop.
- New edits suspend stale mapping. Zoom, pane size, media, fonts and folding
  trigger fresh geometry.
- Scroll-only actions do not alter source, selection, Undo or dirty state.
  Nested and horizontal scrolling stay independent.
- Complex, collapsed or ambiguous content can use a section boundary instead
  of claiming precise line alignment.
- Fixed an empty-list source-mapping loop that could freeze the app.

### Tables, lists, images and HTML

- Replaced equal-width table columns with content-sized columns and a
  font-measured prose cap.
- Allowed cramped tables to use space outside the prose column.
  Narrow panes wrap suitable cells and retain horizontal scrolling where necessary.
- Long links and inline code wrap inside cells without changing preformatted blocks.
- Long tables retain their original header while scrolling; nested tables keep
  their own header, links, selection and horizontal scrolling.
- Fixed clipping of three-/four-digit ordered-list markers.
- Resolved relative images from the document location, including spaces, hashes
  and parent directories, while retaining authored source for notes.
- Accepted trailing whitespace and parameters on raw-HTML fences.
- Replaced guessable block placeholders and unsafe replacement-string handling,
  so literal placeholder text and `$` sequences cannot corrupt block assembly.
- Kept `$` replacement patterns in filenames from corrupting app messages.

### Mermaid, appearance and PDF

- Improved diagram label/shape proportions and allowed flowchart labels a
  wider native wrapping budget while respecting author settings and explicit breaks.
- Measured diagrams outside the zoomed reader, fixing labels clipped after
  insertion or reload at higher zoom.
- Kept valid neighboring diagrams rendering when another diagram is invalid.
- Corrected first-open dark diagrams, stale source restoration and rendering races;
  reject ambiguous or stale diagram edits.
- Removed forced compositing that blurred image/diagram popouts.
- Improved faint dark-diagram borders, connectors and lifelines while retaining
  authored widths/colors, semantic colors and invisible/data-sized strokes.
- Added Clarity, Parchment, Abyss and Ember alongside the existing light/dark
  defaults, with a remembered scheme for each appearance mode.
- Applied scheme colors consistently to syntax, selection, copy controls,
  notes, dialogs and error messages.
- Preserved inherited printer-friendly PDF layout while fixing Mermaid theme
  settlement and restoring the reader's current preference afterward.
- Overlapping exports retain the export appearance until it can safely be released.
  This is not a guarantee of a frozen document snapshot during every export.

### Offline code languages

- Added official offline Prism grammars for Rust, Go, PHP, Ruby, Swift, Kotlin,
  Dart, R, PowerShell, YAML, TOML and Markdown.
- Kept existing grammars, language aliases and exact source-copy behavior.
- Unknown/unlabelled fences stay plain. No language detection, editor coloring,
  inline-code coloring or runtime grammar downloads.
- This adds language components at Prism 1.30.0; it is not a Prism version upgrade.

### Dialogs, updates and installation

- Shared themed messages and confirmations use the selected palette and bundled font.
  Focus stays inside decisions; Cancel is the safe default.
- Queued answers belong to their original question and are rechecked before action.
  Separate Main-owned dialogs can protect shutdown even if the document renderer fails.
- Native file pickers and operating-system warnings remain native.
- Added About with the running version, shared update status and explicit
  Check, Download and Restart & install actions.

  Opening About itself does not contact the update feed.

- Kept updates on this project's own release feed.
- Preserved existing/custom installation directories and checked running app

## Performance, CPU and memory

### Implemented work

- Deferred heavy startup modules and loaded Mermaid only when a diagram needs it.
  Later Word removal eliminated its heavyweight dependency entirely.
- Repaired incremental rendering with stable keyed matching, reused unchanged
  diagrams/images/code, and highlighted only blocks needing work.
- Batched table layout measurements and bulk-detached fresh DOM blocks instead
  of repeating document-wide work for each table or node.
- Debounced search, coalesced zoom work and rendered visible Mermaid diagrams
  first during theme changes. Total rendering work still has to finish.
- Cached heading/table geometry for scrolling, with binary search and bounded
  writes instead of repeated full-document scans.
- Maintained dirty-state answers as documents change rather than rescanning
  every document during close. Added a fast active-editor newline fold.
- Reused unchanged hidden source-measurement spans while refreshing current
  offsets and geometry.
- Avoided unused semver loading and repeated verification of unchanged metadata trees.
- Added a structure-based render-cost estimate and a warning before expensive
  opens/tab activation. It warns; it does not make large files cheap.

### Selected measurements

| Scenario | Recorded result | Limit |
|---|---|---|
| Dense synthetic document render | 1 MB: 41.3 to 5.0 s; 2 MB: 187.1 to 7.8 s | Historical dense fixtures, not every file-open workload. The 5 MB case remained superlinear. |
| Wide-table Markdown parsing, 2.5 MB | 34,339 to 397 ms after marked modernization | Parser only. Prose was essentially unchanged: 92 to 93 ms. |
| Startup without diagrams | 473 to 348 ms with lazy Mermaid | Historical matched launch experiment, not a current startup promise. |
| Mermaid theme change, 20 diagrams | Blocking response about 400 to 85 ms | Full diagram settlement still took roughly 422-450 ms. |
| Zoom burst, 150-table fixture | Settlement about 3,000 to 490 ms | Coalesced work, not eliminated layout or a universal zoom result. |
| Dirty-state close scan, 25 files of 2 MB, CRLF | Raw p95 98.1947 to 1.2792 ms | Historical scan endpoint, not whole shutdown or the later active-editor reconstruction. |
| Small edits, 1 MiB prose, three matched pairs | Whole edited builds 26-31% shorter; current output 94.6-120.5 ms earlier | Hidden-mirror retention only; typing delays still remained. |

- These are separate workloads and source snapshots. Do not add the gains
  together or treat elapsed timings as measured CPU/RAM savings.
- Later active-editor close handling has its own budget evidence in the
  performance audit; it is not the same comparison as the dirty-state scan above.
- Added language coverage has an accepted **performance exception**, not a
  passed gate: representative first-open observed p95 rose from 151.8 to
  203.1 ms, exceeding the 50 ms allowance by 1.3 ms.
- Kept the **400 ms preview pause**. A measured 200 ms trial showed earlier
  previews but wider input delays and was rejected.
- Heavy-document mapping still has measurable delays. No whole-app rewrite,
  smooth-typing guarantee or blanket performance pass is claimed.

### CPU and memory: what the evidence supports

- The inherited fork already had background throttling and 80 ms mousemove
  throttling. Its earlier macOS idle-CPU reduction is **not our measured improvement**.
- New batching, lazy loading, reuse and coalescing avoid unnecessary CPU/layout work.
  Added TOC, sticky-header and source-mapping features also add work.
- Bound pending adoptions, retained document owners and deletion evidence;
  retire associated aliases/state and disconnect closed-drawer observers.
- Removed translation's duplicate document machinery and reused existing DOM
  nodes. Shared inline editing uses weak node references rather than retaining
  detached markup snapshots.
- A historical check opened/closed twelve Mermaid-heavy tabs over three
  GC-stabilized cycles. `heapUsed` returned within **0.0-0.2 MB** of baseline.
  This found no obvious leak in that scenario; it is not a before/after saving.
- No verified project-wide RSS, heap or CPU-percentage reduction is available.
- Removing duplicate packaged libraries reduced an earlier `app.asar` from
  **153.6 MB to 23.2 MB**. That is disk/package size, **not RAM**.
